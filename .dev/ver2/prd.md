# PRD: 팀 대항 토론 모드 (ver2)

원본 계획서: `.dev/debate-classroom/AI_토론_웹사이트_계획서.md` (2026-09-19)
기존 PRD: `.dev/debate-classroom/prd.md` (R1~R72, AC1~AC33 — 1:1 AI 토론. 이미 구현·배포됨)

이 문서의 요구사항 번호는 **ver2 전용**이다. 기존 PRD 번호와 겹치지 않게 `V` 접두어를 쓴다
(V-R1, V-AC1). 기존 번호를 가리킬 때는 `R4`, `R53`처럼 접두어 없이 쓴다.

## Summary

지금 서비스는 학생 한 명이 AI 챗봇과 1:1로 토론한다. ver2는 여기에 **팀 대항 토론**
모드를 더한다. 교사가 학급 학생을 찬성팀·반대팀으로 나누면, 학생들은 한 화면의
**전체 토론방**에서 팀끼리 차례를 번갈아 가며 발언하고, 오른쪽 **팀 채팅**에서 작전을 짠다.
AI는 토론 상대가 아니라 **심판**이다. 전체 토론방 발언이 올라올 때마다 채점하고,
토론이 끝나면 팀 총점·단계별 점수·우승팀과 종합 피드백을 만든다.

토론은 교사가 여는 5단계(토론 시작 → 주장 → 반론 → 반론꺾기 → 최종토론)로 진행된다.
발언권과 타이머는 서버가 결정한다. 한 팀이 발언을 보내거나 60초 안에 못 쓰면 상대 팀으로
차례가 넘어간다. 교사는 **진행 관제실**에서 단계·시간을 통제하고, 공지를 고정하고,
부적절한 발언을 숨기고, AI 점수를 고친다.

기존 1:1 모드는 그대로 둔다. 학급·학생 명단·학급 코드·교사 인증·학년 프리셋·보관함·PDF
기반을 재사용하고, 팀 토론 전용 테이블과 화면을 새로 만든다.

## Problem And Goal

**문제**

1. 1:1 AI 토론은 반 전원이 발언하게 해 주지만, 친구의 주장을 듣고 반박하는 **사람 사이의
   토론**은 연습시키지 못한다. 계획서가 겨냥하는 수업은 팀 대항 교실 토론이다.
2. 교실에서 팀 토론을 하면 발표력 좋은 몇 명이 발언을 독점하고, 교사는 순서·시간 관리에
   묶여 내용 지도를 못 한다.
3. 말로 하는 토론은 기록이 남지 않아 과정 중심 평가 자료로 쓸 수 없다.

**목표**

- 교사가 한 화면(진행 관제실)에서 단계·시간·발언권을 통제한다.
- 발언권을 팀 교대 + 60초 제한으로 서버가 강제해, 순서 있는 토론을 만든다.
- 발언마다 AI 점수와 근거가 남고, 토론이 끝나면 우승팀·종합 피드백·PDF가 나온다.

**성공의 기준이 아닌 것**: AI 점수를 성적에 반영하는 것. 교사가 고칠 수 있는 참고 점수다.

## Users And Use Cases

**U1. 담임 교사**

- 기존 학급에서 "팀 토론 만들기"를 누르고 주제·팀 이름·단계별 시간을 정한다.
- 학급 명단을 찬성팀/반대팀으로 끌어 놓거나 "무작위 배정"을 누른다.
- 수업 시작 전 "입장 열기"를 누른다. 학생들이 기존 학급 코드로 들어와 대기실에 모인다.
- "토론 시작"을 누르고, 단계마다 "다음 단계로"·일시정지·1분 연장을 쓴다.
- 관제실에서 전체 토론방, 두 팀의 채팅, 실시간 점수판을 본다. 필요하면 공지를 고정하고,
  부적절한 발언을 숨기고, 팀 채팅에 경고를 보낸다.
- "토론 종료" 후 결과 보고서에서 AI 점수를 확인·수정하고, "결과 공개"를 눌러 학생에게
  보여준 뒤 PDF를 내려받는다.

**U2. 초등 3~6학년 학생**

- 기존처럼 학급 코드를 넣고 명단에서 이름을 누른다. 열린 팀 토론을 고르면 대기실에서
  주제와 우리 팀을 본다.
- 토론이 시작되면 오른쪽 팀 채팅으로 작전을 짜고, 우리 팀 차례에 전체 토론방에 발언한다.
  먼저 쓰기 시작한 친구가 있으면 그 친구가 끝낼 때까지 기다린다.
- 토론이 끝나고 선생님이 결과를 공개하면 우승팀·팀 점수·전체 피드백을 본다.

**U3. AI 심판 (시스템)**

- 전체 토론방 발언마다 항목별 점수와 한 줄 근거를 매긴다.
- 토론이 끝나면 종합 피드백과 학생별 참여 요약(교사 전용)을 쓴다.

## Pre-Work

- **P1.** 기존 환경 변수와 Supabase 프로젝트를 그대로 쓴다. 새 환경 변수는
  `OPENAI_JUDGE_MODEL` 하나다 (발언별 채점용, 이름만 `.env.example`에 추가).
- **P2.** 발언별 채점 기준표(V-R30 표)의 문안과 학년별 기대 수준을 교사 1명에게 확인받는다.
  3학년·6학년 예시 발언 각 3개를 채점해 보여주는 것이 가장 싼 검증이다.
- **P3.** 시범 학교 네트워크에서 1.5초 간격 폴링이 차단·지연되지 않는지 확인한다
  (계획서의 "웹소켓 허용 여부 확인"을 폴링 구조에 맞게 바꾼 것).
- **P4.** 개발용 Supabase 에서만 `verify:team` 을 돌린다. 운영 DB 에서 돌리지 않는다.

## Non-Goals

계획서에 있지만 이번 범위에 **넣지 않는다**. 이유를 함께 적는다.

- **학생 4자리 PIN** — 기존 결정("아이가 비밀번호를 잊어 수업이 멈추는 것을 막는 게 최우선")을
  유지한다. 대신 한 학생이 두 기기로 들어오면 앞 기기를 끊고 교사에게 알린다(V-R9).
- **토론마다 따로 발급하는 6자리 입장 코드** — 기존 학급 코드(숫자 6자리)를 그대로 쓴다.
  코드가 둘이면 아이들이 헷갈린다.
- **CSV 명단 업로드** — 기존 붙여넣기 등록(R6)으로 충분하다.
- **채점 기준표의 교사 편집(항목·배점 변경)** — 기준표는 코드 파일 하나에 고정한다. 교사는
  발언별 점수를 고칠 수 있다(V-R36). 배점이 바뀌면 DB 제약·프롬프트·합산이 함께 흔들린다.
- **단계 시간 템플릿 저장** — 토론마다 기본값에서 고친다.
- **팀 채팅의 AI 요약** — 교사는 팀 채팅 원문을 관제실에서 읽는다. 호출 비용을 늘리지 않는다.
- **웹소켓·별도 실시간 서버** — 기존 구조(Vercel + 폴링)를 유지한다. 근거는
  `Technical Structure And Changes` 참고.
- **3팀 이상, 모둠별 동시 토론방 여러 개** — 계획서의 향후 확장.
- **AI 근거 자료 추천 준비 단계, 학생별 누적 성장 기록** — 계획서의 향후 확장.
- **팀 토론에서의 길잡이 캐릭터·주제 이탈 소형 모델 판정** — 심판 채점의 태도 항목이 이 역할을
  한다. 부적절 판정(Moderation API, 무료)만 쓴다.
- **학생에게 학생 개인 점수 공개** — 학생 화면은 팀 단위 점수만 보여준다(R53 원칙 유지).
- **기존 1:1 모드 동작 변경** — V-R4의 "한 번에 하나만 열기" 연동 외에는 건드리지 않는다.

## Requirements

### 팀 토론 만들기와 배정

- **V-R1.** 교사는 학급 상세 화면에서 팀 토론을 만든다. 입력: 주제(필수, 100자 이내),
  보충 설명(선택, 300자 이내), 팀 이름 두 개(기본 "찬성팀"/"반대팀", 각 20자 이내),
  단계별 시간(V-R12 기본값, 각 1~20분), 발언 제한 시간(기본 60초, 30~120초),
  점수 공개 방식(V-R34), 발언자 고르게 옵션(V-R27, 기본 꺼짐).
- **V-R2.** 팀 토론은 생성 시 학급 학년을 스냅샷으로 복사한다. `draft` 상태에서만 설정과
  학년을 바꿀 수 있다 (R41과 같은 규칙).
- **V-R3.** 교사는 학급의 활성 학생을 찬성팀/반대팀/미배정 세 칸에 끌어 놓아 배정한다.
  "무작위 배정"은 활성 학생 전원을 두 팀에 인원 차이 1명 이내로 나눈다. 두 팀 인원 차이가
  2명 이상이거나 한 팀이 2명 미만이면 경고 문구를 보이되 저장은 막지 않는다. 배정은
  `draft` 상태와 `open`+`waiting` 단계에서만 바꿀 수 있다.
- **V-R4.** 팀 토론 상태는 `draft` → `open` → `closed`다. "입장 열기"가 `open`으로 바꾼다.
  학급의 "한 번에 하나만 열기"(R11)가 켜져 있으면 1:1 세션과 팀 토론을 **합쳐** 한 번에
  하나만 열 수 있다. 충돌하면 열려 있는 쪽의 주제를 알려준다. 판정과 상태 전이는 한
  트랜잭션에서 한다(동시 클릭에도 두 개가 열리지 않는다).
- **V-R5.** 팀 토론도 보관 → 완전 삭제 두 단계(R66~R70)를 따른다. `open` 상태는 보관·삭제되지
  않는다. 완전 삭제 미리보기는 배정 학생 수, 발언 수, 팀 채팅 수, 채점 건수를 돌려준다.
  학급 보관·삭제 판단(열린 토론이 있으면 거부)에 팀 토론도 포함한다.
  팀 토론에서 발언·팀 채팅을 남긴 학생은 명단에서 삭제하지 않고 비활성 처리한다
  (R7 규칙을 팀 기록까지 확장. `removeOrDeactivateStudent` 가 팀 기록도 본다).

### 학생 입장과 대기실

- **V-R6.** 학생은 기존 흐름(학급 코드 → 명단에서 이름)으로 들어온다. 열린 목록에 1:1 세션과
  함께 **자기가 배정된** `open` 팀 토론이 나온다. 배정되지 않은 팀 토론은 목록에 나오지 않고,
  직접 URL로 들어가도 404다.
- **V-R7.** `waiting` 단계에서는 대기실만 보인다: 주제, 보충 설명, 우리 팀 이름과 팀원 이름,
  "선생님이 토론을 시작하면 열려요". 토론방과 팀 채팅 입력은 없다.
- **V-R8.** 학생은 **자기 팀 채팅만** 읽고 쓸 수 있다. 상대 팀 채팅을 요청하면 서버가 404를
  돌려준다. 학생 폴링 응답에도 상대 팀 채팅이 들어 있지 않다.
- **V-R9.** 한 학생이 다른 기기로 같은 팀 토론에 들어오면 새 기기가 이긴다. 앞 기기의 다음
  요청은 409(`replaced`)를 받고 "다른 기기에서 들어왔어요" 화면으로 바뀐다. 앞 기기가 최근
  30초 안에 활동 중이었다면 교사 관제실에 "중복 접속" 알림을 남긴다.

### 단계 진행과 교사 제어

- **V-R10.** 단계는 `waiting` → `opening` → `claim` → `rebuttal` → `counter` → `final` → `ended`다.
  "토론 시작"이 `opening`으로, "다음 단계로"가 그다음 단계로, "토론 종료"가 어느 단계에서든
  `ended`로 바꾸고 상태를 `closed`로 만든다. 거꾸로 가지 않는다.
- **V-R11.** 단계 시간이 끝나면 자동으로 다음 단계로 넘어가지 **않는다.** 토론방이 잠기고
  "시간이 끝났어요. 선생님이 다음 단계를 열어요"가 표시된다. 시간이 남았을 때 "다음 단계로"를
  누르면 확인 문구 뒤에 넘어간다(= 단계 건너뛰기).
- **V-R12.** 단계별 규칙과 기본 시간:

  | 단계 | 기본 시간 | 토론방 | 첫 차례 | 팀당 발언 상한 |
  | --- | --- | --- | --- | --- |
  | `opening` 토론 시작 | 3분 | 잠김 (팀 채팅만) | — | — |
  | `claim` 주장 | 8분 | 교대 | 찬성 | 없음 |
  | `rebuttal` 반론 | 8분 | 교대 | 반대 | 없음 |
  | `counter` 반론꺾기 | 8분 | 교대 | 찬성 | 없음 |
  | `final` 최종토론 | 6분 | 교대 | 반대 | 2회 |
  | `ended` 종료 | — | 잠김 | — | — |

  `final`에서 두 팀 모두 2회를 쓰면 시간이 남아도 토론방이 잠긴다. 한 팀만 2회를 다 쓰면
  남은 팀의 차례가 이어진다.
- **V-R13.** 교사는 일시정지·재개를 할 수 있다. 일시정지 중에는 단계 시간과 차례 시간이 모두
  멈추고, 학생 화면에 "잠깐 멈췄어요"가 뜨며 발언 전송이 거부된다(팀 채팅은 된다).
  재개하면 남은 시간이 그대로 이어진다.
- **V-R14.** 교사는 "1분 연장"으로 현재 단계의 남은 시간을 60초 늘린다. 시간이 이미 끝난
  단계에도 쓸 수 있고, 그러면 토론방이 다시 열린다.
- **V-R15.** 단계가 바뀌거나 공지가 올라오면 모든 학생 화면에 **3초 안에** 새 단계 이름·남은
  시간·안내가 반영된다.
- **V-R16.** 교사는 전체 공지를 쓸 수 있다(200자 이내). 가장 최근 공지 하나가 전체 토론방
  맨 위에 고정·강조되고, 이전 공지는 토론방 기록에 남는다.
- **V-R17.** 교사는 전체 토론방 발언을 숨기고 되돌릴 수 있다. 숨긴 발언은 학생 화면에
  "선생님이 가린 발언이에요"로만 보이고, 그 발언의 점수는 팀 총점·단계별 점수에서 빠진다.
  원문은 교사 화면과 PDF에 "숨김" 표시와 함께 남는다.
- **V-R18.** 교사는 한 팀의 채팅에 경고 메시지를 보낼 수 있다(200자 이내). 학생 화면에
  "선생님" 이름으로 강조 표시된다.

### 발언권과 시간 초과

- **V-R19.** 발언권과 모든 시간(단계 마감, 차례 마감, 잠금 만료)은 **서버 시각**으로 판정한다.
  응답마다 `serverNow`를 실어 보내고, 클라이언트는 이 값으로 시계 차이를 보정해 남은 시간을
  그린다. 클라이언트 시계로 판정하지 않는다.
- **V-R20.** 교대 단계에서는 한 번에 한 팀만 전체 토론방에 쓸 수 있다. 차례인 팀이 발언
  하나를 보내면 즉시 상대 팀 차례가 되고 차례 시간(기본 60초)이 새로 시작한다.
- **V-R21.** 차례 시간 안에 발언이 없으면 그 차례는 **패스**로 기록되고 상대 팀으로 넘어간다.
  전체 토론방에 "○○팀 패스"가 시스템 메시지로 남는다. 단계 시간이 끝나서 차례가 끊긴 것은
  패스가 아니다.
- **V-R22.** 차례 시간 10초 전에 차례인 팀 학생 전원의 화면에 "10초 남았어요"가 뜬다.
  입력창 위 막대가 남은 시간에 맞춰 줄어든다.
- **V-R23.** 같은 팀이 **자기 차례 두 번을 연속으로 패스**하면 그 팀에 참여 감점 -1점이
  기록되고 교사 관제실에 알림이 뜬다. 감점은 서버가 계산하며 AI가 매기지 않는다.
  세 번째 연속 패스는 새 감점을 만들지 않고, 발언을 한 번 하면 연속 횟수가 0으로 돌아간다.
- **V-R24.** 차례인 팀에서 **먼저 입력을 시작한 학생**이 "발언 중" 잠금을 얻는다. 같은 팀의
  다른 학생 입력창은 막히고 "○○ 친구가 쓰고 있어요"가 보인다. 잠금은 입력할 때마다 연장되고,
  20초 동안 입력이 없으면 풀린다. 두 학생이 동시에 시작해도 한 명만 잠금을 얻는다.
- **V-R25.** 전체 토론방 발언은 1~300자다. 빈 발언·공백만 있는 발언은 보내지 않는다.
  잠금이 없거나 우리 차례가 아니거나 일시정지·잠김 상태면 서버가 409로 거부한다.
- **V-R26.** 단계가 끝나거나 차례가 넘어가 입력 중이던 발언을 보낼 수 없게 되면, 그 글은
  자동으로 우리 팀 채팅에 "(못 보낸 발언)" 표시와 함께 저장된다.
- **V-R27.** "발언자 고르게" 옵션이 켜져 있으면, 차례가 시작되고 **처음 15초** 동안은 이번
  토론에서 이미 2번 이상 말한 학생이 잠금을 얻지 못한다. 단, 같은 팀에 접속 중(최근 10초 안에
  폴링)이면서 2번 미만 말한 팀원이 없으면 제한하지 않는다. 막힌 학생에게는 "아직 말하지 않은
  친구에게 먼저 기회를 줄게요"가 보인다.

### 팀 채팅

- **V-R28.** 팀 채팅은 `opening`부터 `final`까지 언제나 쓸 수 있고, `waiting`과 `ended`에서는
  읽기만 된다. 한 번에 200자, 학생당 2초에 1회로 제한한다(초과 시 429).
- **V-R29.** 팀 채팅 메시지마다 "토론방에 올리기" 버튼이 있다. 누르면 그 문장이 전체 토론방
  입력창에 채워지고 잠금 획득(V-R24)을 시도한다. 차례가 아니면 버튼이 비활성이다.
  보내기 전에 고칠 수 있다.
  이 팀채팅은 교사가 볼 수 있다. 

### AI 발언별 채점

- **V-R30.** 전체 토론방 발언이 저장되면 서버가 AI 채점을 뒤에서 1회 실행한다. 기준표:

  | 항목 | 보는 것 | 점수 | 주로 보는 단계 |
  | --- | --- | --- | --- |
  | 논리성 | 주장과 근거가 이어지는가 | 0~2 | 전체 |
  | 근거의 구체성 | 사례·자료·경험을 들었는가 | 0~1 | 주장, 반론꺾기 |
  | 상대 발언 반영 | 직전 상대 발언을 정확히 짚었는가 | 0~1 | 반론, 반론꺾기 |
  | 단계 적합성 | 지금 단계에 맞는 발언인가 | 0~1 | 전체 |
  | 태도 (감점) | 인신공격, 비속어, 주제 이탈 | 0~-3 | 전체 |

  발언 점수 = 네 항목 합(0~5) + 태도 감점, **0 미만이면 0**. 합산은 서버가 한다.
- **V-R31.** 채점 입력은 주제, 보충 설명, 현재 단계, 발언 팀, 세션 학년 프리셋, 그리고 이번
  발언 이전의 숨기지 않은 전체 토론방 발언(번호 포함)이다. 출력은 항목별 점수, 한 줄 근거,
  대응한 상대 발언 번호(없으면 null)다. 한 줄 근거는 학년 프리셋의 문장 길이·어휘를 따른다.
- **V-R32.** AI에 **학생 이름을 보내지 않는다.** 모든 AI 입력에서 학생은 "찬성팀 학생1"처럼
  토론마다 고정된 가명으로 바뀐다. 팀 이름은 보낸다.
- **V-R33.** 채점 입력에 Moderation 판정 결과를 넘기지 않는다. 태도 감점은 심판이 발언 자체를
  읽고 판단한다 (R50과 같은 이유 — 이중 감점 방지).
- **V-R34.** 점수 공개 방식은 `live`(발언 옆 배지 + 팀 점수판을 학생에게 실시간 표시)와
  `after_end`(결과 공개 뒤에만 표시) 중 하나다. 기본값은 3~4학년 `after_end`,
  5~6학년 `live`다. 교사는 항상 실시간으로 본다.
- **V-R35.** 채점이 실패하면 5초 뒤 1번 다시 시도한다. 그래도 실패하면 `failed`로 저장하고
  발언 옆에 "채점 대기"를 표시한다. 교사는 관제실·보고서에서 "다시 채점"을 누를 수 있다.
  채점 실패가 발언 전송이나 차례 이동을 막아서는 안 된다.
- **V-R36.** 교사는 발언별 항목 점수를 고칠 수 있다(각 항목 범위 안에서). 고치면 발언 점수와
  팀 점수가 다시 합산되고, 수정 전·후 값, 교사, 시각이 이력으로 남는다. 교사가 고친 점수는
  "다시 채점"으로 덮어쓰지 않는다.
- **V-R37.** 한 발언에 대한 자동 채점은 DB 제약으로 1회만 실행된다 (`claimScoring`과 같은 방식).

### 종료와 결과

- **V-R38.** "토론 종료"를 누르면 즉시 200을 돌려주고, 뒤에서 결과 생성을 시작한다.
  결과 생성은 채점 중(`pending`)인 발언을 최대 60초 기다린 뒤 진행한다.
- **V-R39.** 팀 총점 = 그 팀의 숨기지 않은 발언 점수 합 + 연속 패스 감점. 단계별 점수도 같은
  규칙으로 단계마다 낸다. `failed` 발언은 0점으로 치고 "채점 대기 N건"을 결과에 표시한다.
  모두 서버가 계산한다.
- **V-R40.** 우승팀은 총점이 높은 팀이다. 동점이면 반론꺾기(`counter`) 단계 점수가 높은 팀,
  그것도 같으면 **무승부**다. 발언이 하나도 없으면 결과를 만들지 않고 "발언이 없어 결과가
  없어요"를 표시한다.
- **V-R41.** AI는 종료 후 한 번 호출되어 (a) 팀별 가장 좋았던 논증 1개와 그 이유,
  (b) 놓친 반박 지점 1~2개, (c) 다음 토론을 위한 제안 1~2개, (d) 학생별 잘한 점 한 가지를
  쓴다. 점수·우승팀은 AI가 정하지 않는다(서버 값을 입력으로 준다). 학생 이름 대신 가명을
  쓰고, 서버가 가명을 이름으로 되돌려 저장한다. 피드백은 학년 프리셋을 따르고 격려하는 말투로 쓴다.
- **V-R42.** 결과 생성은 토론당 1회만 자동 실행된다(DB 제약). 실패하면 `failed`로 저장하고
  교사 보고서에 "다시 만들기" 버튼을 둔다. 교사가 점수를 고치면 총점·우승팀은 즉시 다시
  계산하되 AI 피드백은 다시 만들지 않는다.
- **V-R43.** 학생은 교사가 "결과 공개"를 누르기 전까지 결과를 보지 못한다("선생님이 결과를
  준비하고 있어요"). 공개 뒤 학생 결과 화면에는 우승팀, 두 팀의 총점·단계별 점수, 전체
  피드백(a~c)만 있다. **학생별 발언 수·잘한 점·개인 점수는 학생 응답에 담지 않는다.**
- **V-R44.** 교사 결과 보고서에는 V-R43의 내용에 더해 발언별 점수·근거·수정 이력, 학생별
  발언 수와 잘한 점, 연속 패스 기록, 숨긴 발언, 채점 대기 건수가 있다.
- **V-R45.** 교사는 결과를 PDF로 내려받는다. 표지(학급, 학년, 주제, 날짜, 팀 구성), 점수 요약,
  우승팀, 종합 피드백, 학생별 참여 요약, 전체 토론방 기록 전문(단계 구분, 발언별 점수·근거,
  숨김·패스 표시)을 담는다. 팀 채팅은 넣지 않는다. 결과 생성 전이면 표지에 "결과 생성 전"을 표기한다.

### 부적절 발언

- **V-R46.** 전체 토론방 발언과 팀 채팅은 저장 후 뒤에서 OpenAI Moderation API로 판정한다.
  부적절이면 교사 관제실 상단 알림에 학생 이름·채널·발언 일부가 뜬다. 자동으로 숨기지 않는다
  (숨김은 교사가 V-R17로 한다). 판정 실패는 조용히 넘어가고 전송을 막지 않는다.

### 화면

- **V-R47.** 학생 토론 화면: 상단에 단계 이름·단계 남은 시간·"지금은 ○○팀 차례"와 차례 남은
  시간 막대, 왼쪽 전체 토론방, 오른쪽 팀 채팅. 가로 폭 768px 미만(태블릿 세로)에서는 두 칸을
  탭으로 바꾸고, 우리 팀 차례가 되면 "토론방" 탭에 강조 표시를 띄운다.
- **V-R48.** 교사 관제실: 단계·타이머 제어 버튼, 전체 토론방, 두 팀 채팅(나란히), 실시간 점수판
  (팀 총점·단계별), 학생 접속 상태와 발언 수, 알림 영역(부적절·중복 접속·연속 패스), 공지 입력.
- **V-R49.** 학생·교사 화면은 **1.5초 간격**으로 폴링한다. 폴링 한 번은 DB 왕복 1회로 끝난다.
  응답은 마지막으로 받은 메시지 번호 이후의 새 메시지만 담는다. 갱신 중에 스크롤 위치와
  입력 중인 글이 흔들리지 않는다.

### 비용

- **V-R50.** AI 호출은 전체 토론방 발언 1개당 채점 1회 + 토론당 결과 1회다. 팀 채팅은 AI를
  호출하지 않는다(Moderation 제외). 발언 모델은 `OPENAI_JUDGE_MODEL`, 결과 모델은 기존
  `OPENAI_SCORING_MODEL`을 쓴다. 코드에 모델 이름을 박지 않는다.

## Acceptance Criteria

- **V-AC1.** 학급 상세에서 팀 토론을 만들면 기본값(찬성팀/반대팀, 3·8·8·8·6분, 60초)이 채워져
  있고, 학급 학년이 스냅샷된다. `open` 이후 설정 변경 API는 409다. (V-R1, V-R2)
- **V-AC2.** 활성 학생 7명에서 "무작위 배정"을 누르면 4:3으로 나뉜다. 한 팀에 5명, 다른 팀에
  2명을 두면 경고가 보이지만 저장된다. (V-R3)
- **V-AC3.** "한 번에 하나만" 켜진 학급에서 1:1 세션이 열려 있을 때 팀 토론 "입장 열기"는
  거부되고 1:1 세션 주제가 문구에 나온다. 반대 방향도 같다. 같은 팀 토론에 "입장 열기"를
  동시에 두 번 보내도 한 번만 성공한다. (V-R4)
- **V-AC4.** `open` 팀 토론은 보관·삭제가 409다. 닫은 뒤 보관 → 미리보기 → 삭제가 동작하고,
  미리보기에 발언 수·팀 채팅 수·채점 건수가 나온다. 팀 토론에서만 발언한 학생을 명단에서
  삭제하면 비활성으로 바뀌고 발언 기록이 남는다. (V-R5)
- **V-AC5.** 배정된 학생의 열린 목록에 팀 토론이 보이고, 미배정 학생에게는 보이지 않으며
  미배정 학생이 상태 API를 직접 부르면 404다. (V-R6)
- **V-AC6.** `waiting` 단계 학생 화면에 주제·우리 팀·팀원이 보이고 입력창이 없다. (V-R7)
- **V-AC7.** 찬성팀 학생 쿠키로 반대팀 채팅을 요청하면 404이고, 찬성팀 학생의 폴링 응답
  JSON 어디에도 반대팀 채팅 내용이 없다. (V-R8)
- **V-AC8.** 같은 학생으로 기기 A, B 순서로 들어가면 A의 다음 폴링이 409 `replaced`를 받고,
  관제실에 "중복 접속" 알림이 뜬다. (V-R9)
- **V-AC9.** 단계 시간이 끝나면 토론방이 잠기고 단계가 그대로다. 교사가 "다음 단계로"를 누르면
  3초 안에 모든 학생 화면의 단계 이름이 바뀐다. (V-R10, V-R11, V-R15)
- **V-AC10.** `claim`은 찬성, `rebuttal`은 반대, `counter`는 찬성, `final`은 반대 차례로
  시작한다. `final`에서 두 팀이 각 2회 발언하면 시간이 남아도 토론방이 잠긴다. (V-R12)
- **V-AC11.** 차례 남은 시간 40초에서 일시정지하고 30초 뒤 재개하면 남은 시간이 약 40초다.
  일시정지 중 발언 API는 409, 팀 채팅은 성공한다. (V-R13)
- **V-AC12.** 시간이 끝난 단계에서 "1분 연장"을 누르면 토론방이 다시 열리고 단계 남은 시간이
  60초다. (V-R14)
- **V-AC13.** 공지를 두 번 쓰면 두 번째만 맨 위에 고정되고 첫 번째는 기록에 남는다. (V-R16)
- **V-AC14.** 교사가 발언을 숨기면 학생 화면에 가림 문구가 보이고, 그 팀 총점에서 그 발언
  점수만큼 빠진다. 되돌리면 다시 더해진다. (V-R17, V-R39)
- **V-AC15.** 찬성팀이 발언을 보내면 즉시 반대팀 차례가 되고 차례 시간이 60초로 시작한다.
  반대팀 차례에 찬성팀 학생이 발언 API를 부르면 409다. (V-R20, V-R25)

## Technical Structure And Changes

**스택** — 기존 저장소를 따른다. 계획서의 기술 선택과 다른 부분은 이유를 적는다.

- Next.js 16 App Router + React 19 + TypeScript + Tailwind 4 (`package.json`). 이 버전은 API가 다를
  수 있으므로 `node_modules/next/dist/docs/` 를 먼저 읽는다 (`AGENTS.md`).
- **데이터베이스: Supabase (Postgres)** — 저장소가 답한다: `@supabase/supabase-js` 의존성,
  `supabase/migrations/`, `.env.example` 의 `NEXT_PUBLIC_SUPABASE_URL`. 사용자에게 묻지 않았다.
  접근은 기존과 같이 서버에서 service role 키로만 (`src/lib/supabase/admin.ts`, `server-only`).
  RLS를 켜고 정책을 만들지 않는다.
- **실시간: 웹소켓 대신 1.5초 폴링 + 서버 시각 기반 지연 판정.** 계획서는 웹소켓 서버 1대를
  두지만, 이 프로젝트는 Vercel 서버리스 + 폴링 구조이고 "완전 실시간은 복잡도 대비 이득 없음"을
  이미 결정했다. 차례 시간 초과 같은 시간 이벤트는 백그라운드 타이머가 아니라, **모든 폴링과
  쓰기 요청이 먼저 호출하는 SQL 함수(`team_tick`)가 행 잠금 안에서 처리**한다. 누군가 한 명이라도
  폴링하는 한 1.5초 안에 반영되고, 행 잠금이 중복 기록을 막는다. Supabase Realtime은 RLS
  전면 거부 방침과 충돌하고(브라우저가 DB 채널에 붙어야 한다) 서버 권한 판정이 흩어지므로 쓰지 않는다.
- **AI: OpenAI 유지** (계획서의 Claude API 대신). 기존 키·AI SDK(`ai`, `@ai-sdk/openai`)·
  구조화 출력(`generateObject`) 패턴을 그대로 쓴다. 발언 채점 `OPENAI_JUDGE_MODEL`(기본
  `gpt-4.1-mini`, 3~5초 목표), 결과 `OPENAI_SCORING_MODEL`, 부적절 `omni-moderation-latest`.
- 뒤에서 끝나야 하는 작업(채점, 결과 생성, Moderation)은 `runInBackground`(`src/lib/background.ts`).
- PDF: 기존 `@react-pdf/renderer` + `public/fonts/NotoSansKR-*.ttf`.
- 배포: Vercel, Node.js 런타임. `runtime = 'edge'`를 쓰지 않는다.

턴 규칙(단계별 첫 차례, 상한, 다음 차례 결정)은 SQL 함수 안에 있지만, 같은 규칙을
`src/lib/team/rules.ts` 에 순수 함수로도 두어 단위 테스트한다. 두 곳이 어긋나지 않도록
`verify:team` 이 실제 SQL 결과를 같은 시나리오로 확인한다.

**발언 흐름** (`POST /api/team/speak`)

인증 → 기기 확인 → 본문 검증(1~300자) → `team_speak` RPC(차례·잠금·상태 검사와 저장이 한 트랜잭션)

채점·Moderation 실패는 응답에 영향이 없다.

**종료 흐름**

`team_control(end)` → 200 즉시 → `runInBackground(buildTeamReport)`: `team_reports` 에 pending 행
insert(23505면 종료) → `pending` 발언을 최대 60초 폴링 대기 → 서버가 점수·우승 계산 → AI 피드백
(가명) → 이름 복원 → 저장.

## Risks And Open Decisions

- **폴링 지연이 체감될 수 있다.** 차례 넘김이 최대 1.5초 늦게 보이고, 60초 차례에서는 문제없지만
  잠금 경쟁은 "먼저 누른 사람"이 아니라 "먼저 서버에 닿은 사람"이 이긴다. 30명 × 1.5초 = 초당 약
  20요청이다. H3에서 느리면 학생 폴링만 1초로 줄이거나, 서버 권한은 유지한 채 Supabase Realtime
  **Broadcast**(DB 직결 없이 서버가 "바뀌었음" 신호만 보냄)를 붙이는 것이 다음 수순이다.
- **`team_tick` 이 폴링마다 행 잠금을 잡는다.** 30명 동시 폴링이 한 행에서 줄을 선다. 함수가 짧아
  문제없을 것으로 보지만 검증되지 않았다. 느리면 "마감 전이면 잠금 없이 스냅샷만" 경로를 먼저 둔다.
- **아무도 폴링하지 않으면 시간이 흘러도 패스가 기록되지 않는다.** 교사 관제실이 열려 있는 한
  폴링이 있으므로 수업 중에는 문제가 없다. 전원이 나가면 다음 접속 때 밀린 차례가 한꺼번에
  패스로 정리된다(`team_tick` 은 반복 처리해야 한다).
- **PIN 없이 이름 클릭이라 친구 이름으로 발언할 수 있다.** 팀 토론에서는 1:1보다 위험이 크다.
  중복 접속 알림(V-R9)으로 교사가 알아챌 수 있게만 했다. 실제로 문제가 되면 계획서의 4자리 PIN을
  별도 요구사항으로 추가한다 — **미확정 결정**. PIN을 넣으면 명단 화면·학생 테이블·입장 API가 바뀐다.
- **발언별 AI 점수의 흔들림.** 0~5점 척도에서 1점 차이는 크다. 교사 수정 기능을 두었고, H4에서
  교사 점수와 비교한다. 흔들림이 크면 채점 온도를 0으로, 기준표 문안을 더 구체적으로.
- **점수 공개 기본값(3~4학년 `after_end`)은 계획서의 "저학년"을 해석한 것이다.** 사용자 확인이
  필요하다면 이 한 줄만 바꾸면 된다 (`rules.ts` 의 기본값).
- **단계 시간이 끝나도 자동으로 넘어가지 않는 것은 계획서 해석이다.** 계획서는 "교사가 정한 시간에
  따라 진행"과 "다음 단계로" 버튼을 둘 다 적었다. 교사 통제권을 우선했다. 자동 진행을 원하면
  `team_tick` 에 단계 전이를 넣으면 된다.
- **팀 인원 3~6명 기준은 권장이다.** 학급 전체(25~30명)를 두 팀으로 나누면 팀당 13~15명이 되어
  대부분이 발언하지 못한다. 이번 범위는 토론 1개 = 2팀이므로, 나머지 학생은 미배정(관전 없음)으로
  두거나 여러 번 나눠 진행한다. 모둠별 동시 토론방은 비목표(향후 확장).
- **발언 채점 문맥을 전부 넘긴다.** 계획서는 "최근 20개 + 이전 요약"이지만, 발언이 최대 300자 ×
  약 80개라 전부 넘겨도 모델 문맥에 들어간다. 요약 호출을 없애 비용과 실패 지점을 줄였다.
- **토론 1회 비용은 개발 초기에 산정한다.** 발언 60~80개 × 소형 모델 1회 + 결과 1회. `verify:team`
  실행 후 OpenAI 사용량으로 실제 값을 기록한다.
