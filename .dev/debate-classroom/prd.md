# PRD: 초등 토론 챗봇 교실 (debate-classroom)

## Summary

초등학교 4학년 학생이 교사가 정한 토론 주제에 대해 찬성/반대 입장을 고르고, AI 챗봇과 1:1로 토론하는 웹 서비스다. 챗봇은 학생이 고른 입장의 **반대편에 서서** 초등학생 눈높이의 부드러운 말투로 근거를 대고 되묻는다. 교사는 대시보드에서 반 전체의 진행 상황을 수 초 간격으로 관망하고, 주제에서 벗어나거나 부적절한 발언을 한 학생을 즉시 식별하며, 수업이 끝나면 세션 전체를 PDF로 내려받는다.

학급에는 **학년(초등 3~6학년)** 이 설정되어 있고, 챗봇의 어휘와 문장 길이가 학년에 맞춰 달라진다. 토론이 끝나면 OpenAI가 학생의 대화를 **4개 항목 20점 만점으로 채점**하고, 잘한 점과 다음에 해볼 것을 알려준다. 점수와 피드백은 학생과 교사가 모두 본다.

학생은 로그인하지 않는다. 교사가 발급한 6자리 학급 코드를 입력하고 명단에서 본인 이름을 고르면 바로 토론에 들어간다.

## Problem And Goal

**문제**

1. 초등학교 4학년이 자기 의견에 대한 반론을 마주하고 스스로 근거를 다시 세워보는 연습 기회가 적다. 교실 토론은 발표력이 좋은 소수 학생이 독점하기 쉽고, 나머지 학생은 한 마디도 못 하고 수업이 끝난다.
2. 교사가 30명의 토론을 동시에 지켜보며 "누가 딴 얘기를 하고 있는지"를 파악하는 것은 물리적으로 불가능하다.
3. 토론 수업의 결과물이 남지 않아 평가·기록·학부모 공유에 쓸 자료가 없다.

**목표**

- 반 전원이 동시에, 각자 최소 8회 이상 발언하는 토론 경험을 갖는다.
- 교사가 한 화면에서 반 전체의 참여도와 이탈 여부를 파악한다.
- 수업 종료 시점에 학생별 토론 기록이 담긴 PDF 한 부가 자동으로 만들어진다.

**성공의 기준이 아닌 것**: 학생의 논리력을 점수화하는 것. 이번 범위는 "토론이 일어나게 하고, 교사가 지켜보고, 기록이 남는 것"까지다.

## Users And Use Cases

**U1. 담임 교사**

- 운영자에게 받은 초대 코드로 가입하고, 이메일/비밀번호로 로그인한다.
- 학급을 만들면서 **학년(3~6)** 을 고르고, 학생 이름 25~30개를 한 번에 붙여넣어 등록한다. 6자리 학급 코드가 발급된다.
- 수업 시작 전 토론 주제("숙제는 없어져야 한다")로 세션을 만들고, 학생 1인당 메시지 상한을 정한다.
- 수업 시작과 동시에 "토론 시작"을 누른다. 학생들이 들어온다.
- 순회하면서 대시보드를 본다. 빨간 배지가 뜬 학생에게 직접 가서 지도한다.
- 수업이 끝나면 "토론 종료"를 누른다. 학생별 토론 점수가 자동으로 채점되어 대시보드에 나타난다.
- 점수와 피드백이 포함된 PDF를 내려받는다.

**U2. 초등학교 4학년 학생**

- 교실 태블릿/노트북으로 서비스에 접속해 칠판에 적힌 6자리 코드를 입력한다.
- 우리 반 명단에서 자기 이름을 찾아 누른다.
- 주제를 읽고 "나는 찬성" 또는 "나는 반대"를 고른다.
- 챗봇과 대화한다. 챗봇이 계속 반대 의견을 말하고 질문을 던져서, 학생은 계속 생각해서 답한다.
- 메시지 상한에 도달하거나 교사가 종료하면 대화가 잠기고 마무리 화면을 본다.
- 마무리 화면에서 **내 토론 점수(20점 만점)와 항목별 점수**, 잘한 점 2가지, 다음에 해볼 것 1가지를 확인한다.

## Pre-Work

구현 시작 전에 다음이 준비되어 있어야 한다.

- **P1.** Supabase 프로젝트 생성. `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` 확보.
- **P2.** OpenAI API 키 확보 (`OPENAI_API_KEY`). 결제 수단이 연결된 계정일 것.
- **P3.** 학생 세션 쿠키 서명용 랜덤 시크릿 생성 (`STUDENT_SESSION_SECRET`, 32바이트 이상).
- **P4.** 최초 교사 가입에 쓸 초대 코드 1개를 `invite_codes` 테이블에 시드로 넣는다. 시드 스크립트에 포함한다.
- **P5.** PDF에 한글을 렌더링하기 위한 Noto Sans KR (Regular/Bold) TTF를 `public/fonts/`에 배치한다.
- **P6.** 학년별 프리셋(R42 표)과 채점 루브릭(R46 표)을 코드 상수로 옮기기 전에 문안을 확정한다. 교사 1명에게 3학년·6학년 예시 응답을 보여주고 눈높이가 맞는지 확인받는 것이 가장 저렴한 검증이다.

값 자체는 이 문서에 적지 않는다. `.env.example`에 키 이름만 남긴다.

## Non-Goals

이번 범위에 **넣지 않는다**. 좋아 보여도 확장하지 않는다.

- 학생 개인 계정, 비밀번호, 이메일 수집
- 학생 간 채팅, 그룹 토론, 팀전
- 교사가 진행 중인 학생 대화에 실시간으로 개입(메시지 전송, 입력 차단)하는 기능
- 챗봇이 이탈한 학생을 자동으로 주제로 되돌리는 유도 로직
- 성적 산출, 생활기록부 반영, 학기 단위 누적 성장 리포트
- 학생 간 점수 순위, 리더보드, 반 평균 대비 내 위치 표시
- 학년별 커리큘럼 연계, 교과 단원 매핑
- 교사가 AI 점수를 수정하거나 직접 채점하는 기능
- 공개 회원가입 (초대 코드 없는 가입)
- 다국어, 영어 UI
- 음성 입력/출력
- 학생이 자기 대화를 PDF로 받는 기능
- 웹소켓 기반 완전 실시간 스트리밍 대시보드 (폴링으로 충분하다고 결정)

## Requirements

### 교사 인증

- **R1.** 교사는 `/teacher/signup`에서 이메일, 비밀번호, 이름, **초대 코드**를 입력해 가입한다. 유효하지 않거나 비활성이거나 사용 횟수가 소진된 초대 코드는 가입을 거부하고 "초대 코드가 올바르지 않습니다"를 표시한다.
- **R2.** 가입 성공 시 초대 코드의 사용 횟수가 1 증가한다. `max_uses`에 도달한 코드는 이후 가입에 쓸 수 없다.
- **R3.** 교사는 `/teacher/login`에서 이메일/비밀번호로 로그인하고, 로그아웃할 수 있다. 로그인하지 않은 상태로 `/teacher/**`에 접근하면 로그인 화면으로 리다이렉트된다.
- **R4.** 교사는 자신이 만든 학급과 세션만 조회·수정할 수 있다. 다른 교사의 리소스 id로 요청하면 404를 반환한다.

### 학급과 학생 명단

- **R5.** 교사는 학급 이름을 입력해 학급을 만든다. 생성 시 서버가 중복되지 않는 **6자리 학급 코드**(혼동되는 글자 `0 O 1 I L`을 제외한 대문자+숫자)를 발급한다.
- **R6.** 교사는 학생 이름을 줄바꿈으로 구분한 텍스트로 한 번에 붙여넣어 등록한다. 같은 학급 안에서 이름이 중복되면 등록을 거부하고 어떤 이름이 중복인지 알려준다.
- **R7.** 교사는 학생 이름을 개별로 추가·수정·삭제할 수 있다. 이미 토론에 참여해 메시지를 남긴 학생은 삭제 대신 비활성 처리되며 기존 기록은 유지된다.
- **R8.** 교사는 학급 코드를 재발급할 수 있다. 재발급하면 이전 코드는 즉시 무효가 된다.

### 토론 세션

- **R9.** 교사는 학급 안에 토론 세션을 만든다. 입력 항목은 주제(필수, 100자 이내), 보충 설명(선택, 300자 이내), 학생 1인당 메시지 상한(기본 30, 3~100 범위)이다.
- **R10.** 세션 상태는 `draft` → `open` → `closed` 3단계다. 교사가 "토론 시작"을 누르면 `open`, "토론 종료"를 누르면 `closed`가 된다. `closed`에서 다시 열 수 없다.
- **R11.** 학급에는 **"한 번에 하나의 세션만 열기"** 옵션이 있다(기본 켜짐). 켜져 있으면 이미 `open`인 세션이 있는 상태에서 다른 세션을 열려 할 때 거부하고, 열려 있는 세션 이름을 알려준다. 끄면 여러 세션을 동시에 열 수 있다.
- **R12.** 학생은 `open` 상태의 세션에만 입장할 수 있다. 열린 세션이 없으면 "아직 토론이 시작되지 않았어요"를 표시한다. 학급에 열린 세션이 둘 이상이면 학생이 주제 목록에서 하나를 고른다.

### 학생 입장

- **R13.** 학생은 `/join`에서 6자리 학급 코드를 입력한다. 코드가 유효하면 해당 학급의 활성 학생 명단이 표시된다. 유효하지 않으면 "코드를 다시 확인해 주세요"를 표시한다.
- **R14.** 학생이 명단에서 자기 이름을 누르면 서버가 서명된 httpOnly 쿠키(학급 id, 학생 id, 만료 12시간)를 발급한다. 학생용 화면은 이 쿠키로만 인증한다.
- **R15.** 학생은 토론 시작 화면에서 주제를 읽고 **찬성/반대 중 하나를 반드시 선택**해야 대화를 시작할 수 있다. 선택한 입장은 해당 세션에서 변경할 수 없다.
- **R16.** 이미 참여한 학생이 같은 세션에 다시 들어오면, 이전 대화가 그대로 복원되고 이어서 대화할 수 있다.

### 챗봇 토론

- **R17.** 챗봇은 학생이 고른 입장의 **반대편**을 대화 내내 유지한다. 학생이 설득하거나 입장을 바꿔달라고 요청해도 입장을 바꾸지 않는다.
- **R18.** 챗봇의 모든 응답은 (a) 초등학교 4학년이 이해할 수 있는 어휘와 3~5문장 분량, (b) 존중하는 부드러운 말투, (c) **반론 근거 최소 1개**, (d) **학생에게 되묻는 질문 1개**를 포함한다.
- **R19.** 챗봇은 자기가 AI라는 사실을 숨기지 않으며, 사실 관계가 불확실한 통계나 출처를 지어내지 않는다.
- **R20.** 챗봇 응답은 학생 화면에 **스트리밍**으로 표시된다. 응답 생성 중에는 입력창이 비활성화된다.
- **R21.** 학생 메시지 수가 세션의 상한에 도달하면 입력창이 잠기고 "오늘 토론은 여기까지예요" 마무리 화면이 표시된다. 이미 진행 중인 챗봇 응답은 끝까지 표시된다.
- **R22.** 교사가 세션을 종료하면 학생 화면은 최대 10초 안에 잠금 상태로 전환되고, 이후 메시지 전송 요청은 서버에서 거부된다.
- **R23.** 학생 메시지는 500자로 제한한다. 빈 메시지와 공백만 있는 메시지는 전송되지 않는다.

### 이탈·부적절 발언 감지

- **R24.** 학생이 메시지를 보낼 때마다 서버는 두 가지 판정을 수행한다.
  - (a) OpenAI Moderation API로 **부적절 여부** 판정 (욕설, 폭력, 성적 내용, 자해 등)
  - (b) 소형 모델로 세션 주제와의 **관련성** 판정 → `on_topic` / `off_topic`
- **R25.** 판정 결과는 메시지 단위로 저장되며, 최종 등급은 `on_topic`(정상) / `off_topic`(노랑) / `inappropriate`(빨강)이다. 부적절 판정은 관련성 판정보다 우선한다.
- **R26.** 판정 호출이 실패하거나 타임아웃되면 해당 메시지는 `on_topic`으로 저장하되 `판정 실패` 플래그를 남긴다. **판정 실패가 토론 응답을 막아서는 안 된다.**
- **R27.** 판정은 챗봇 응답 생성을 지연시키지 않는다. 응답 스트리밍과 병렬로 수행한다.

### 교사 대시보드

- **R28.** 세션 대시보드는 학생 타일 그리드를 보여준다. 각 타일에는 이름, 선택한 입장(찬성/반대), 보낸 메시지 수 / 상한, 마지막 활동 시각, 경고 배지가 표시된다.
- **R29.** 대시보드는 **3초 간격으로 자동 갱신**된다. 갱신 중에도 화면이 깜빡이거나 스크롤 위치가 튀지 않는다.
- **R30.** `inappropriate` 발언이 있는 학생은 **빨간 배지**로 표시되고, 대시보드 **상단에 고정된 경고 영역**에 학생 이름과 문제 메시지 일부가 나열된다. `off_topic`만 있는 학생은 노란 배지로 표시되며 상단 고정 영역에는 올라가지 않는다.
- **R31.** 교사가 학생 타일을 누르면 그 학생의 전체 대화가 패널로 열리고, 문제로 판정된 메시지는 배경색으로 강조된다.
- **R32.** 교사는 경고를 "확인함"으로 처리할 수 있다. 확인한 경고는 상단 고정 영역에서 사라지지만 학생 상세와 PDF에는 그대로 남는다.
- **R33.** 대시보드 상단에 세션 요약을 표시한다: 참여 학생 수 / 전체 학생 수, 찬성·반대 분포, 총 메시지 수, 경고 건수.

### 기록 내보내기

- **R34.** 교사는 세션 상세에서 PDF를 내려받는다. PDF에는 표지(학급명, 주제, 날짜, 참여 인원), 세션 요약, 학생별 섹션(이름, 입장, 메시지 수, 전체 대화 전문, 문제 판정 표시)이 포함된다.
- **R35.** PDF의 한글이 깨지지 않아야 한다. 30명 × 30메시지 분량에서도 생성이 완료되어야 한다.
- **R36.** `open` 상태 세션도 PDF를 받을 수 있으나, 표지에 "진행 중 시점 기준"이라고 표기한다.

### 비용·남용 방지

- **R37.** 학생 1인당 메시지 상한(R9, R21)이 세션 단위 비용 상한 역할을 한다. 상한을 넘는 요청은 서버에서 거부한다.
- **R38.** 학생 1명당 메시지 전송은 5초에 1회로 제한한다(서버 측). 초과 시 429와 안내 문구를 반환한다.
- **R39.** OpenAI API 키는 서버에서만 사용하며 클라이언트 번들에 포함되지 않는다.

### 학년별 눈높이 조정

- **R40.** 교사는 학급을 만들거나 수정할 때 **학년을 3~6 중에서 선택**한다. 기본값은 4학년이다. 학년은 필수 값이다.
- **R41.** 세션은 생성 시점에 학급의 학년을 **스냅샷으로 복사해 보관**한다. `draft` 상태에서는 세션의 학년을 바꿀 수 있고, `open` 이후에는 바꿀 수 없다. 학급의 학년을 나중에 바꿔도 이미 만들어진 세션에는 영향을 주지 않는다.
- **R42.** 학년별 프리셋이 코드 한 곳에 상수로 정의되고, 토론 프롬프트와 채점 프롬프트에 주입된다. 각 프리셋은 최소한 응답 문장 수 범위, 한 문장 최대 길이, 어휘 지침, 예시 소재 범위를 담는다.

  | 학년 | 문장 수 | 한 문장 길이 | 어휘·표현 |
  | --- | --- | --- | --- |
  | 3학년 | 2~3문장 | 25자 이내 | 아주 쉬운 낱말만. 예시는 학교·집·놀이 범위 |
  | 4학년 | 3~4문장 | 35자 이내 | 교과서 수준 낱말 |
  | 5학년 | 4~5문장 | 45자 이내 | "왜냐하면 ~때문이야" 같은 근거 구조 사용 |
  | 6학년 | 4~6문장 | 55자 이내 | 조건·반례 표현 허용("항상 그런 건 아니야", "만약 ~라면") |

- **R43.** 챗봇 응답은 해당 세션 학년의 문장 수·문장 길이 범위를 지킨다. R18의 요건(반론 근거 1개 + 되묻는 질문 1개)은 학년과 무관하게 항상 유지된다.
- **R44.** 학년은 학급 목록, 세션 대시보드 헤더, PDF 표지에 표시된다.

### 토론 점수 채점

- **R45.** 학생의 토론이 끝나면(교사가 세션을 종료했거나 학생이 메시지 상한에 도달) 서버가 그 학생의 대화 전체를 OpenAI로 **1회 채점**한다. 참여 1건당 자동 채점은 1회만 수행한다.
- **R46.** 채점 루브릭은 4개 항목 × 5점 = **20점 만점**이다.

  | 항목 | 무엇을 보는가 |
  | --- | --- |
  | 근거 대기 | 자기 주장에 이유를 붙였는가 |
  | 상대 말에 답하기 | 챗봇의 반론과 질문에 실제로 응답했는가 |
  | 생각 이어가기 | 대화가 진행되며 새 근거를 더하거나 생각이 깊어졌는가 |
  | 알기 쉽게 말하기 | 문장이 남이 이해할 수 있게 쓰였는가 |

- **R47.** 채점 결과는 항목별 점수(1~5), 총점, **항목별 한 줄 근거**, **잘한 점 2가지**, **다음에 해볼 것 1가지**를 포함한다.
- **R48.** 채점 기준은 **세션 학년에 맞춰 조정된다.** 3학년의 5점과 6학년의 5점은 같은 글이 아니다. 채점 프롬프트에 학년 프리셋을 주입하고, "이 학년에서 기대할 수 있는 수준"을 기준으로 매기게 한다.
- **R49.** 피드백 문장은 해당 학년 프리셋의 어휘·문장 길이를 따르고, 격려하는 말투로 쓴다. 부족한 점을 지적할 때도 비난·훈계 표현을 쓰지 않는다.
- **R50.** 채점은 **주제 이탈·부적절 판정 결과를 반영하지 않는다.** 태도 문제와 토론 능력은 별개 축으로 다루며, 채점 프롬프트에 판정 결과를 넘기지 않는다.
- **R51.** 학생 메시지가 **3개 미만**이면 채점하지 않고 상태를 `skipped`로 저장한다. 학생 화면과 대시보드에 "평가하기에는 대화가 너무 짧아요"를 표시한다.
- **R52.** 채점에 실패하면 상태를 `failed`로 저장한다. 학생 화면에는 점수 대신 "오늘 토론하느라 수고했어요" 마무리만 표시하고, 교사 대시보드에는 실패 표시와 **다시 채점 버튼**을 제공한다. 재채점은 교사가 명시적으로 눌렀을 때만 수행한다.
- **R53.** 학생은 마무리 화면에서 자기 총점, 항목별 점수, 잘한 점, 다음에 해볼 것을 본다. **다른 학생의 점수나 반 평균, 순위는 학생 화면에 표시하지 않는다.**
- **R54.** 교사 대시보드의 학생 타일에 총점이 표시된다. 채점 전에는 "채점 중", 건너뛴 경우 "대화 부족"으로 표시한다. 상세 패널에는 항목별 점수와 근거, 피드백 전문이 표시된다.
- **R55.** 세션 요약(R33)에 채점 완료 인원 수와 반 평균 총점이 추가된다.
- **R56.** PDF의 학생별 섹션에 총점, 항목별 점수, 잘한 점, 다음에 해볼 것이 포함된다.
- **R57.** 채점 호출은 학생 1명당 1회이므로 비용은 참여 인원 수에 비례한다. 자동 채점이 중복 실행되지 않도록 참여 단위로 잠금 처리한다.

## Acceptance Criteria

- **AC1.** 잘못된 초대 코드로 가입을 시도하면 계정이 생성되지 않고 오류 문구가 표시된다. `max_uses`가 1인 코드로 두 번째 가입을 시도하면 거부된다. (R1, R2)
- **AC2.** 로그아웃 상태에서 `/teacher`로 이동하면 `/teacher/login`으로 리다이렉트된다. 교사 A로 로그인한 상태에서 교사 B의 학급 id를 URL에 넣으면 404가 뜬다. (R3, R4)
- **AC3.** 학급을 만들면 6자리 코드가 화면에 표시되고, 이름 25개를 붙여넣어 등록하면 명단에 25명이 나타난다. 중복 이름이 포함되면 등록이 거부되고 중복 이름이 문구에 나온다. (R5, R6)
- **AC4.** "한 번에 하나만 열기"가 켜진 학급에서 이미 열린 세션이 있을 때 다른 세션의 "토론 시작"을 누르면 거부 문구가 뜬다. 옵션을 끄면 두 세션이 동시에 `open`이 된다. (R11)
- **AC5.** 학생이 코드를 입력하고 이름을 고르면 토론 시작 화면이 뜨고, 찬성/반대를 고르지 않으면 "시작하기" 버튼이 비활성 상태다. (R13, R15)
- **AC6.** 학생이 브라우저 탭을 닫았다가 같은 기기에서 다시 들어오면 이전 대화가 그대로 보인다. (R14, R16)
- **AC7.** 학생이 "찬성"을 골랐을 때 챗봇의 첫 응답부터 10번째 응답까지 모두 반대 입장을 유지하고, 매 응답에 물음표로 끝나는 질문이 최소 1개 포함된다. 학생이 "너도 찬성이지?"라고 물어도 입장을 바꾸지 않는다. (R17, R18)
- **AC8.** 챗봇 응답이 한 번에 나타나지 않고 글자 단위로 이어서 표시되며, 표시되는 동안 입력창이 비활성이다. (R20)
- **AC9.** 메시지 상한을 3으로 설정한 세션에서 학생이 3번째 메시지를 보낸 뒤 입력창이 잠기고 마무리 화면이 뜬다. 이후 API를 직접 호출해도 거부된다. (R21, R37)
- **AC10.** 교사가 "토론 종료"를 누르면 학생 화면이 10초 안에 잠금으로 바뀐다. (R22)
- **AC11.** 학생이 "오늘 급식 뭐야?"를 보내면 해당 메시지가 `off_topic`으로 저장되고, 대시보드 타일에 노란 배지가 뜬다. 상단 고정 경고 영역에는 올라가지 않는다. (R24, R25, R30)
- **AC12.** 욕설이 포함된 메시지를 보내면 `inappropriate`로 저장되고, 대시보드 타일에 빨간 배지가 뜨며 상단 고정 영역에 학생 이름이 나타난다. (R24, R25, R30)
- **AC13.** 판정용 API 호출이 실패하도록 강제해도 학생은 챗봇 응답을 정상적으로 받고, 해당 메시지에 `판정 실패`가 기록된다. (R26)
- **AC14.** 학생이 메시지를 보낸 뒤 교사 대시보드에 3~5초 안에 메시지 수 증가가 반영된다. 갱신 시 열려 있던 학생 상세 패널이 닫히지 않는다. (R29, R31)
- **AC15.** 교사가 경고를 "확인함" 처리하면 상단 영역에서 사라지고, 새로고침해도 다시 나타나지 않는다. 학생 상세에는 여전히 강조 표시가 남아 있다. (R32)
- **AC16.** 학생 5명 × 메시지 5개 세션에서 PDF를 내려받으면 한글이 정상 렌더링되고, 5명 전원의 대화 전문이 포함되며, 문제 판정된 메시지가 시각적으로 구분된다. (R34, R35)
- **AC17.** 같은 학생이 1초 간격으로 메시지를 두 번 보내면 두 번째 요청이 429로 거부된다. (R38)
- **AC18.** 프로덕션 빌드 산출물을 검색했을 때 `OPENAI_API_KEY`나 `SUPABASE_SERVICE_ROLE_KEY` 값이 나타나지 않는다. (R39)
- **AC19.** 학급 생성 화면에서 학년을 고르지 않으면 4학년이 기본 선택되어 있고, 3~6 외의 값을 API로 보내면 거부된다. (R40)
- **AC20.** 3학년 학급과 6학년 학급에서 같은 주제로 각각 대화하면, 3학년 응답이 6학년 응답보다 눈에 띄게 짧고 쉬운 낱말로 구성된다. 두 응답 모두 되묻는 질문을 포함한다. (R42, R43)
- **AC21.** 세션을 `open`한 뒤 학급의 학년을 5학년으로 바꿔도, 진행 중인 세션의 챗봇 응답 기준은 바뀌지 않는다. (R41)
- **AC22.** 학생이 메시지 5개를 보내고 교사가 세션을 종료하면, 60초 안에 그 학생의 채점이 완료되어 대시보드 타일에 총점이 뜬다. 학생 마무리 화면에도 총점·항목별 점수·잘한 점 2개·다음에 해볼 것 1개가 표시된다. (R45, R46, R47, R53, R54)
- **AC23.** 학생 메시지가 2개인 참여는 채점되지 않고 `skipped`로 저장되며, 양쪽 화면에 "대화가 너무 짧아요" 안내가 뜬다. (R51)
- **AC24.** 채점 호출이 실패하도록 강제하면 학생 화면에 점수 없이 마무리 문구만 뜨고, 대시보드에 실패 표시와 다시 채점 버튼이 나타난다. 버튼을 누르면 재채점이 수행된다. (R52)
- **AC25.** 같은 참여에 대해 세션 종료와 상한 도달이 동시에 발생해도 채점 호출은 1회만 실행된다. (R45, R57)
- **AC26.** 학생 마무리 화면 응답 어디에도 다른 학생의 이름·점수나 반 평균이 포함되지 않는다. 대시보드와 PDF에는 반 평균이 표시된다. (R53, R55, R56)

## Verification - Agent

에이전트가 직접 실행해 증거를 남길 수 있는 검증.

1. `pnpm typecheck` — 타입 오류 0.
2. `pnpm lint` — 오류 0.
3. `pnpm build` — 빌드 성공.
4. `rg -n "sk-|SERVICE_ROLE" .next/static` — 매치 0건 (AC18).
5. Supabase 마이그레이션 적용 후 `\d` 조회로 테이블 9개와 제약 조건 존재 확인.
6. 시드 스크립트 실행 → 초대 코드 1개, 데모 교사 1명, 학급 1개, 학생 5명 생성 확인.
7. API 통합 테스트 (Vitest + 로컬 Supabase 또는 테스트 스키마):
   - 잘못된 초대 코드 가입 거부 (AC1)
   - 타 교사 리소스 접근 시 404 (AC2)
   - 중복 이름 일괄 등록 거부 (AC3)
   - 단일 활성 세션 옵션 위반 시 거부 (AC4)
   - 메시지 상한 초과 요청 거부 (AC9)
   - 종료된 세션에 메시지 전송 시 거부 (AC10)
   - 5초 내 재전송 429 (AC17)
   - 판정 함수를 실패하도록 목킹해도 응답 경로가 성공 (AC13)
8. 판정 로직 단위 테스트: 주제 "숙제는 없어져야 한다"에 대해 `["숙제가 많으면 놀 시간이 없어요", "오늘 급식 뭐야?", "<욕설 샘플>"]` 3개 입력이 각각 `on_topic`/`off_topic`/`inappropriate`로 분류되는지 (AC11, AC12).
9. PDF 생성 함수를 5명×5메시지 픽스처로 호출 → 파일이 생성되고 0바이트가 아니며, 텍스트 추출 시 학생 5명의 이름이 모두 포함되는지 (AC16).
10. 개발 서버를 띄우고 교사 가입 → 학급 생성 → 세션 생성 → 학생 입장 → 메시지 1건 → 대시보드 반영까지를 스크립트로 한 번 통과시키고 결과를 기록한다.
11. 학년 프리셋 단위 테스트: 3/4/5/6학년 프리셋이 모두 정의되어 있고, 프롬프트 빌더가 세션 학년의 문장 수·문장 길이 지침을 실제로 프롬프트 문자열에 포함하는지 (AC20). 학급 학년 변경이 기존 `open` 세션의 스냅샷 값을 바꾸지 않는지 (AC21).
12. 채점 파이프라인 테스트:
    - 메시지 5개 픽스처 → 4개 항목 점수가 모두 1~5 정수, 총점이 항목 합과 일치, 잘한 점 2개·다음 할 것 1개가 비어 있지 않음 (AC22)
    - 메시지 2개 픽스처 → `skipped` 저장, 모델 호출 0회 (AC23)
    - 채점 함수를 실패하도록 목킹 → `failed` 저장, 학생 조회 API가 점수 없이 200 반환, 재채점 API 호출 시 성공 (AC24)
    - 세션 종료와 상한 도달을 연속 호출 → 채점 모델 호출 1회 (AC25)

## Technical Structure And Changes

빈 디렉터리에서 시작하는 신규 프로젝트다. 기존 코드 관례는 없다.

**스택**

- 프레임워크: **Next.js (App Router) + React**, TypeScript
- 스타일: Tailwind CSS + shadcn/ui
- 데이터베이스: **Supabase (Postgres)** — 사용자가 지정. 저장소가 비어 있어 코드에서 유추할 근거가 없었고, 확인 질문으로 확정했다.
- DB 접근: `@supabase/supabase-js`. 모든 DB 접근은 **서버(Route Handler / Server Component / Server Action)에서 service role 키로만** 수행한다. 브라우저는 DB에 직접 접근하지 않는다.
- 인증: **Supabase Auth의 이메일/비밀번호** 방식을 교사 인증에 사용한다. 결정된 "이메일+비밀번호 직접 구현"의 의도(구글/외부 SSO를 쓰지 않는다)를 유지하면서, 비밀번호 해싱·세션·재설정 메일을 직접 만들지 않아 보안 책임을 줄이기 위함이다. 초대 코드 검증은 우리 코드에서 수행한 뒤에만 Supabase 계정을 생성한다.
- 학생 인증: 인증 없음. `jose`로 서명한 httpOnly 쿠키(`ss_token`, 12시간)에 `{ classId, studentId }`를 담는다.
- AI: **OpenAI**. 토론 응답은 범용 모델(`OPENAI_DEBATE_MODEL`, 기본 `gpt-4.1`), 주제 관련성 판정은 소형 모델(`OPENAI_TRIAGE_MODEL`, 기본 `gpt-4.1-mini`), 부적절 판정은 **Moderation API**(`omni-moderation-latest`, 무료), 토론 채점은 범용 모델(`OPENAI_SCORING_MODEL`, 기본 `gpt-4.1`)을 **구조화 출력(JSON 스키마)** 으로 호출한다. AI SDK(`ai` + `@ai-sdk/openai`)로 스트리밍과 `generateObject`를 사용한다.
- PDF: `@react-pdf/renderer`를 Node 런타임 Route Handler에서 사용. `public/fonts/`의 Noto Sans KR을 임베딩한다.
- 배포: Vercel. 함수는 기본 Node.js 런타임(Fluid Compute)을 쓴다. 스트리밍에 edge 런타임은 쓰지 않는다.

**메시지 처리 흐름** (`POST /api/debate/message`)

1. 쿠키 검증 → `participation` 조회
2. 세션 `open` 확인, 메시지 상한 확인, 5초 rate limit 확인 → 위반 시 즉시 거부
3. 학생 메시지 저장 (`seq` 증가)
4. **병렬 시작**: (a) 판정 파이프라인(Moderation + 관련성) → `moderation_flags` 저장, (b) 토론 모델 스트리밍
5. 스트림을 클라이언트로 전달, 완료 시 봇 메시지 저장 및 `student_message_count`, `last_activity_at` 갱신
6. 판정이 실패해도 4-(b)와 5는 영향받지 않는다

**세션 종료 → 채점 흐름**

채점 트리거는 두 곳이다. ① 교사가 세션을 `closed`로 전이할 때, 해당 세션의 모든 참여에 대해 ② 학생이 메시지 상한에 도달했을 때, 그 참여 하나에 대해. 두 경로 모두 다음 절차를 따른다.

1. `debate_scores`에 `status='pending'` 행을 `on conflict do nothing`으로 삽입 → 실패하면 종료 (중복 방지)
2. 학생 메시지 수 < 3이면 `status='skipped'`로 갱신하고 종료 (모델 호출 없음)
3. 대화 전문 + 주제 + 학생 입장 + **학년 프리셋** + 루브릭을 넘겨 구조화 출력으로 채점
4. 성공 시 `status='done'`으로 점수·근거·피드백 저장, 실패 시 `status='failed'`와 `error` 저장
5. 세션 종료 경로는 참여를 순차 처리하되, 교사의 종료 응답을 블로킹하지 않는다. 종료 API는 즉시 200을 반환하고 채점은 뒤에서 진행되며, 대시보드가 폴링으로 `pending → done` 전이를 보여준다

**학년 프리셋 계약** (R42)

프리셋은 `lib/grade-presets.ts` 한 파일에만 정의하고, 토론 프롬프트 빌더와 채점 프롬프트 빌더가 모두 이 상수를 읽는다. 프리셋을 코드 여러 곳에 흩뿌리지 않는다. 각 프리셋은 `{ grade, sentenceRange, maxSentenceLength, vocabularyGuide, exampleDomains, scoringExpectation }` 형태를 갖는다. `scoringExpectation`은 "이 학년에서 5점을 받을 만한 답변은 어떤 모습인가"를 서술한 문장으로, R48을 구현한다.

**챗봇 시스템 프롬프트 요건** (R17~R19, R43을 코드로 옮길 때의 계약)

- 대화 상대의 **학년**과 그 학년의 프리셋(문장 수, 문장 길이, 어휘 지침, 예시 소재)을 주입
- 토론 주제와 **학생의 입장**을 주입하고, 챗봇은 그 반대 입장을 맡는다고 고정
- 매 응답: **학년 프리셋의 문장 수·문장 길이 범위**를 지키고, 반론 근거 1개 이상, 되묻는 질문 1개로 마무리
- 어려운 한자어·전문 용어 금지, 존중하는 말투, 비꼬기·훈계 금지
- 학생이 입장 변경을 요청하거나 설득해도 입장을 유지
- 통계·출처를 지어내지 않기, 무섭거나 자극적인 예시 금지
- 주제에서 벗어난 학생 발언에 대해 훈계하지 않고 자연스럽게 자기 입장 논의를 이어감 (자동 유도는 비목표)

**채점 프롬프트 요건** (R46~R50을 코드로 옮길 때의 계약)

- 입력: 토론 주제, 학생이 고른 입장, 학생/챗봇 대화 전문, 학년 프리셋(`scoringExpectation` 포함)
- **입력에 판정 결과(`moderation_flags`)를 넣지 않는다** (R50)
- 출력: 구조화 스키마 — 4개 항목 각각 `{ score: 1..5, reason: string }`, `strengths: [string, string]`, `nextStep: string`
- 총점은 모델이 아니라 **서버에서 4항목을 합산**해 계산한다 (산술 오류 방지)
- 채점 기준은 학년 프리셋의 기대 수준에 맞춘다. 초등 3학년에게 중학생 수준의 논증을 요구하지 않는다
- `strengths`와 `nextStep`은 학년 프리셋의 어휘·문장 길이를 따르고, "~하지 못했어요" 대신 "다음에는 ~해보자" 형태로 쓴다
- 학생 이름을 출력에 포함하지 않는다

**빌드/스크립트**: `pnpm dev`, `pnpm build`, `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm db:migrate`, `pnpm db:seed`.

## Risks And Open Decisions

- **주제 관련성 판정의 오탐이 가장 큰 품질 리스크다.** 초등학생은 개인 경험담과 비유로 논지를 편다("우리 형은 숙제 안 하는데 시험 잘 봐요"). 이걸 이탈로 잡으면 교사 대시보드가 노란 배지로 뒤덮여 쓸모가 없어진다. 판정 프롬프트에 "간접적 근거, 개인 경험, 비유는 주제 관련으로 본다"를 명시하고 H3에서 실제로 확인한다.
- **교사 인증에 Supabase Auth를 쓰는 것은 "직접 구현" 결정에서 한 발 비켜난 선택이다.** 외부 SSO를 쓰지 않는다는 의도는 유지된다. 되돌리려면 T5만 다시 쓰면 되고 스키마는 그대로 쓸 수 있다.
- **학생 이름 클릭 방식은 본인 확인을 하지 않는다.** 친구 이름을 누를 수 있다. 교실 내부 사용이라 위험도가 낮다고 판단해 수용했으나, 잘못 눌렀을 때의 복구 절차(교사가 참여 기록을 삭제하고 다시 입장시키기)는 이번 범위에 없다. 실사용에서 문제가 되면 별도 요구사항으로 추가한다.
- **3초 폴링 × 30명 × 여러 학급의 부하는 검증되지 않았다.** 대시보드 조회는 집계 쿼리 1회로 끝나도록 설계하되, 실제 수업에서 느려지면 폴링 간격 조정 또는 Supabase Realtime 전환을 검토한다.
- **모델 이름(`gpt-4.1`, `gpt-4.1-mini`)은 환경 변수로 뺀다.** 구현 시점에 가용한 모델로 교체될 수 있으며, 교체가 코드 변경을 요구해서는 안 된다.
- **비용 상한은 학생별 메시지 수만으로 건다.** 교사 계정당 월 예산 상한은 이번 범위 밖이다. 초대 코드로 가입이 통제되므로 1차에서는 충분하다고 판단했다.
- **AI 채점의 신뢰도가 가장 검증하기 어려운 부분이다.** 같은 대화를 두 번 채점하면 점수가 1~2점 흔들릴 수 있다. 이번 범위에서는 점수를 성적에 쓰지 않기로 했으므로(비목표) 허용 가능한 오차로 본다. H8에서 교사 판단과의 차이를 확인하고, 흔들림이 크면 채점 온도를 낮추거나 항목 정의를 더 구체화한다.
- **학생에게 점수를 그대로 보여주기로 한 결정에는 교실 리스크가 따른다.** 아이들이 서로 점수를 비교하게 된다. 이를 완화하려고 학생 화면에서 반 평균·순위·타 학생 점수를 전부 제외했고(R53), 피드백 말투를 격려형으로 고정했다(R49). 그래도 문제가 되면 세션별 공개 토글을 추가하는 것이 다음 수순이다.
- **학년은 학급 단위로만 정한다.** 한 세션에 여러 학년이 섞인 수업(방과후, 동아리)은 지원하지 않는다. 필요해지면 참여 단위 학년으로 확장할 수 있으나 이번 범위 밖이다.
- **학년 프리셋 4개가 실제로 구별되게 동작할지는 프롬프트 품질에 달렸다.** 모델이 지침을 무시하고 비슷한 길이로 답할 수 있다. T25 이후 H7로 반드시 눈으로 확인한다.
- **세션 종료 시 30명 채점이 동시에 돈다.** 순차 처리 시 마지막 학생은 수십 초를 기다린다. AC22는 60초 기준이며, 초과하면 소량 동시 실행(3~5개)으로 조정한다.
- **세션 종료 후 학생이 자기 대화를 다시 볼 수 있는지는 미결이다.** 현재 설계는 쿠키가 살아 있는 12시간 동안 잠긴 상태로 열람 가능하다. 이걸 명시적 기능으로 다듬을지는 실사용 후 결정한다.

## Implementation Result Report Contract

구현 완료 보고 시 다음을 반드시 포함한다.

1. **요구사항 대조표** — R1~R57 각각에 대해 `구현됨 / 부분 구현 / 미구현`과 해당 파일 경로. 부분·미구현은 이유를 한 줄로.

3. **에이전트 검증 출력** — `typecheck`, `lint`, `build`, `test`, 키 노출 검색의 실제 출력. 실패가 있으면 그대로 붙인다.
4. **생성/변경 파일 목록** — 경로와 한 줄 설명.
5. **DB 변경** — 적용한 마이그레이션 파일, 생성된 테이블, 되돌리기 명령.

7. **범위에서 벗어난 발견** — 구현 중 발견했으나 이 PRD 밖이라 손대지 않은 것.
