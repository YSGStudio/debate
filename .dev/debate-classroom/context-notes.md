## 구현 시 주의점

- **service role 키는 절대 클라이언트로 새지 않게 한다.** DB 접근 모듈은 `server-only` 임포트를 붙인다.
- RLS는 켜되 정책을 만들지 않는다(전면 거부). anon 키가 노출돼도 데이터가 읽히지 않는 상태가 기본값이다.
- 판정 파이프라인은 **반드시 응답 스트리밍과 분리**한다. 판정 실패가 아이의 대화를 끊으면 안 된다 (R26).
- 모델 이름은 코드에 박지 말고 환경 변수(`OPENAI_DEBATE_MODEL`, `OPENAI_TRIAGE_MODEL`)로 받는다.
- 부적절 판정은 OpenAI Moderation API(무료)를 쓴다. 소형 모델은 주제 관련성 판정에만 쓴다.
- 대시보드 폴링은 집계 쿼리 1회로 끝내도록 설계한다. 학생 30명마다 쿼리를 도는 구조가 되면 안 된다.
- 학생 UI는 태블릿 세로가 1차 대상이다. 터치 타겟을 크게, 글자를 크게.
- PDF는 Noto Sans KR 임베딩 없이는 한글이 전부 깨진다. T22 시작 전에 `public/fonts/` 배치를 먼저 확인한다.
- **학년 프리셋은 `lib/grade-presets.ts` 한 곳에만 둔다.** 토론 프롬프트와 채점 프롬프트가 같은 상수를 읽어야 한다. 프리셋이 코드 여러 곳에 흩어지면 학년을 늘릴 때 반드시 어긋난다.
- **채점 총점은 모델이 아니라 서버에서 합산한다.** 모델에게 산술을 맡기면 항목 합과 총점이 어긋나는 응답이 나온다.
- **채점 프롬프트에 `moderation_flags`를 넘기지 않는다.** 태도(이탈·부적절)와 토론 능력은 별개 축이라는 것이 명시적 결정이다.
- 채점 중복 실행은 `debate_scores.participation_id` unique + `insert ... on conflict do nothing` 으로 막는다. 애플리케이션 레벨 플래그로 막으려 하지 않는다 (세션 종료와 상한 도달이 동시에 발생할 수 있다).
- 세션 종료 API는 채점 완료를 기다리면 안 된다. 30명이면 교사가 수십 초를 기다리게 된다. 즉시 200을 반환하고 대시보드 폴링이 `pending → done`을 보여준다.
