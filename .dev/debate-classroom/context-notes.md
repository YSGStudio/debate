# Context Notes: debate-classroom

`implement`가 같은 탐색을 반복하지 않도록 남기는 기반 노트.

## 저장소 현황

> 아래 "빈 디렉터리" 기록은 프로젝트 시작 시점의 것이다. 지금은 구현이 끝났고
> `main` 브랜치가 https://github.com/YSGStudio/debate (public) 에 올라가 있다.
> 코드 관례는 `CLAUDE.md` 를 먼저 볼 것.

- (시작 시점) 작업 디렉터리는 완전히 비어 있었다. 따라야 할 기존 코드 관례가 없어 T1에서 전부 새로 정했다.
- DB를 유추할 근거가 없어 사용자에게 확인 질문으로 확정했다 → **Supabase (Postgres)**.

## 세션 환경

- 플랫폼 darwin, 셸 zsh.
- Vercel 플러그인이 세션에 로드되어 있다. 기본 가정: Next.js App Router, Vercel 배포, 함수는 Node.js 런타임(Fluid Compute). **`runtime = 'edge'`를 쓰지 않는다** — 스트리밍은 Node 런타임에서 그대로 동작한다.
- Vercel CLI가 구버전(50.32.5)이다. 배포 단계에서 `npm i -g vercel@latest` 권장.
- Vercel MCP 서버는 미인증 상태다. 인증이 필요한 작업은 사용자에게 요청해야 한다.
- Supabase는 Vercel Marketplace 연동으로 붙일 수 있다. 연동 시 `vercel:marketplace` 스킬을 먼저 읽는다.

## 승인 이후 결정 (구현 중 사용자 요청으로 추가·변경)

| 항목 | 결정 | 배경 |
| --- | --- | --- |
| 학급 코드 | 알파벳+숫자 → **숫자 6자리** | 초4가 칠판을 보고 옮겨 적기 어려웠다. 숫자만 쓰면 대소문자·유사 글자 문제가 사라져 `0`·`1`도 제외할 필요가 없다 |
| 토론 교수법 | `prompts/debate-guide.ts` 로 분리 | 반박 방식·질문 수준·관점 전환을 코드가 아니라 지침 파일에서 고칠 수 있게 |
| 첫 인사 | 별도 라우트 | 찬반 선택 시 "나는 찬성이야" 를 학생 메시지로 보내던 방식이 상한을 깎고 채점 대화에 섞였다 |
| 채점 | 4항목 20점 → **5영역 100점 + 이탈 감점** | 토론 과정(주장→근거→반론→재반박)을 세분해서 보려면 20점으로는 부족했다 |
| 맞춤법 평가 | 삭제 | 새 기준이 핵심 평가 요소가 아니라고 명시 |
| 태도와 점수 | **R50 원칙이 뒤집힘** | 원래 "태도와 토론 능력은 별개 축" 이었으나 100점 루브릭이 이탈 감점을 포함한다. 단 `moderation_flags` 를 넘기지 않는 구현 규칙은 유지 |
| 길잡이 | 판정 호출에 코칭 판정을 얹음 | 별도 호출은 메시지마다 비용이 두 배. 토론 챗봇은 이탈을 혼내지 않으므로 역할이 비어 있었다 |
| 삭제 | **보관함 두 단계** | 한 번의 실수로 한 학기 기록이 사라지는 것을 막는다 |
| 점수 공개 | 학생도 100점 총점을 본다 | 사용자 지정. 대신 학생 화면에서 반 평균·순위는 계속 제외 |

## 구현 시 주의점

- **service role 키는 절대 클라이언트로 새지 않게 한다.** DB 접근 모듈은 `server-only` 임포트를 붙인다.
- RLS는 켜되 정책을 만들지 않는다(전면 거부). anon 키가 노출돼도 데이터가 읽히지 않는 상태가 기본값이다.
- 판정 파이프라인은 **반드시 응답 스트리밍과 분리**한다. 판정 실패가 아이의 대화를 끊으면 안 된다 (R26).
- 모델 이름은 코드에 박지 말고 환경 변수(`OPENAI_DEBATE_MODEL`, `OPENAI_TRIAGE_MODEL`)로 받는다.
- 부적절 판정은 OpenAI Moderation API(무료)를 쓴다. 소형 모델은 주제 관련성 판정에만 쓴다.
- 대시보드 폴링은 집계 쿼리 1회로 끝내도록 설계한다. 학생 30명마다 쿼리를 도는 구조가 되면 안 된다.
- 학생 UI는 태블릿 세로가 1차 대상이다. 터치 타겟을 크게, 글자를 크게.
- PDF는 Noto Sans KR 임베딩 없이는 한글이 전부 깨진다. `public/fonts/` 배치를 먼저 확인한다.
- **분량 규칙은 시스템 프롬프트 맨 끝에 둔다.** 교수법 지침이 길어지자 모델이 학년을 잊고
  3학년에게 55자 문장을 썼다. 맨 끝으로 옮기고 자가 점검을 지시하니 34자로 잡혔다.
- **길잡이 안내는 관련성 판정과 어긋나면 안 된다.** 판정이 이탈인데 칭찬하면 학생이
  점수 안내를 믿지 못한다. `triage.ts` 가 판정을 우선해 코칭을 맞춘다.
- **완전 삭제는 보관된 것만.** DB 쿼리에도 `.not("archived_at","is",null)` 이 걸려 있어
  라우트를 우회해도 목록에서 바로 사라지지 않는다.
- 검증 스크립트가 코드 변경을 못 따라가는 일이 두 번 있었다(학급 코드 규칙, saveFlag 시그니처).
  기능을 바꾸면 `scripts/verify-*.mjs` 도 함께 본다.
- **학년 프리셋은 `lib/grade-presets.ts` 한 곳에만 둔다.** 토론 프롬프트와 채점 프롬프트가 같은 상수를 읽어야 한다. 프리셋이 코드 여러 곳에 흩어지면 학년을 늘릴 때 반드시 어긋난다.
- **채점 총점은 모델이 아니라 서버에서 합산한다.** 모델에게 산술을 맡기면 항목 합과 총점이 어긋나는 응답이 나온다.
- **채점 프롬프트에 `moderation_flags`를 넘기지 않는다.** 태도(이탈·부적절)와 토론 능력은 별개 축이라는 것이 명시적 결정이다.
- 채점 중복 실행은 `debate_scores.participation_id` unique + `insert ... on conflict do nothing` 으로 막는다. 애플리케이션 레벨 플래그로 막으려 하지 않는다 (세션 종료와 상한 도달이 동시에 발생할 수 있다).
- 세션 종료 API는 채점 완료를 기다리면 안 된다. 30명이면 교사가 수십 초를 기다리게 된다. 즉시 200을 반환하고 대시보드 폴링이 `pending → done`을 보여준다.
